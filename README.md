# 技术编辑选题推荐系统

面向技术编辑的选题推荐网页：编辑输入兴趣短文与六个主题的精确篇数配额，系统从 30 篇
本地文章中选出 6 篇组成阅读队列，在满足**主题精确配额**与**作者不重复**的前提下，
最大化加权相关度目标，并按每次两篇的节奏逐步揭示。

新增**版本对读**：选一篇库内文章作原稿，粘贴修订新稿（≤1200 字、≤10 句），系统按
。！？ 切句后用**独立的**字符 2~3 元 TF-IDF 做句子级对齐，并排展示对应、改写、拆句、
移位、新增、删除及双方原文字符范围。

## 技术栈

- **FastAPI**：HTTP 接口与演示页面
- **scikit-learn**：字符 2~3 元 TF-IDF（`TfidfVectorizer(analyzer="char", ngram_range=(2,3))`）
  与余弦相似度
- **SQLite**（WAL 模式）：会话状态、异步重算任务、排除集、揭示票据的持久化
- 原生 HTML/CSS/JS 前端，无构建步骤

## 快速开始

### Docker Compose（推荐）

```bash
docker compose up --build
# 浏览器打开 http://localhost:8000
```

数据通过命名卷 `recommender-data` 持久化到 `/data/recommender.db`，容器重启后
已揭示前缀、兴趣、配额与排除集全部保留。

### 本地直接运行

```bash
pip install -r requirements.txt
RECOMMENDER_DB=./data/recommender.db uvicorn app.main:app --host 0.0.0.0 --port 8000
# 浏览器打开 http://localhost:8000
```

### 运行测试

```bash
pip install -r requirements.txt pytest httpx
pytest
```

## 数据

`app/articles_data.py` 内置 30 篇中文文章，每篇含 `id / 标题 / 正文 / 单一主题 / 作者`：

- 6 个主题（人工智能、医疗健康、金融投资、旅游地理、美食烹饪、体育竞技），每主题 5 篇；
- 10 位作者，每人 3 篇且分布在 3 个不同主题；同一主题内 5 位作者互不相同。
  因此标准“每主题一篇”的队列天然满足作者不重复，而约束校验对任意配额仍然生效。

## 推荐算法

### 相关度

1. TF-IDF **只在 30 篇文章正文上 `fit`**，兴趣短文只做 `transform`，特征空间与
   IDF 权重完全由文章决定；
2. 特征为字符二元、三元组（已断言词表中不存在单字特征）；
3. 兴趣向量与每篇文章向量计算余弦相似度，截断到 `[0,1]` 作为相关度。

### 全局最优队列

求解器 `app/optimizer.py` 用逐主题组合枚举 + 分支定界求**精确全局最优**（非近似）：

- 六个主题按配额 `q_t` 枚举候选组合，强制作者互不重复；
- 给定入选文章集合，由重排不等式，按相关度降序放入权重降序的位置即最优排列；
- 目标函数：`Σ_{pos=1..6} (7 - pos) × 相关度`，位置权重为 6,5,4,3,2,1；
- 存在已揭示前缀时，前缀的位置与文章固定，只对剩余位置重新求全局最优；
- 分支定界的上界忽略跨主题作者冲突（只会高估），保证不剪掉真正的最优解；
- 单元测试中与全暴力枚举对拍，多次随机相关度/配额下结果完全一致；
- 平局按 `article_id` 确定性打破，重复求解结果稳定。

## 揭示规则与并发语义

- 每次点击揭示**两篇**，已揭示文章及其顺序**永久固定**并占用主题配额；
- 可随时修改兴趣、配额或排除/取消排除未揭示文章：未揭示位置按新条件重新全局优化，
  已揭示前缀保持不变；
- 无可行解时保留已揭示内容并停止揭示，接口返回明确原因（如某主题候选不足）；
- **同一条件（世代 generation）和同一进度点的“下一组”只推进一次**：
  进程内写锁串行化所有请求，并以 2 秒宽限窗口（可用环境变量 `REVEAL_CLAIM_TTL` 调整）
  识别并发批次，窗口内重复/并发请求复用首个请求的结果（`idempotent=true`）而不重复推进；
  窗口过后人工的下一次点击正常开启新一轮揭示；
- **慢重算可并发改条件，迟到结果不得揭示旧推荐**：每次条件变更生成新世代并把旧任务
  标记为 `stale`，后台 worker 写回前再次核对世代号，过期结果一律拒绝落库；
- 重算失败只把任务标记 `failed`，**不推进进度**，揭示接口会拒绝并提示；
- 所有状态落盘，**进程重启后已揭示前缀、世代、条件完整恢复**。

## HTTP 接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| `GET` | `/api/status` | 当前状态、最新任务、完整推荐计划、文章清单 |
| `GET` | `/api/articles/{id}` | 单篇文章正文 |
| `PUT` | `/api/condition` | 修改兴趣和/或配额（请求体含 `interest`、`quotas`、可选 `compute_delay_ms`） |
| `POST` | `/api/exclusions` | 排除一篇未揭示文章（`article_id`） |
| `DELETE` | `/api/exclusions/{id}?compute_delay_ms=` | 取消排除 |
| `POST` | `/api/reveal` | 揭示下一组两篇 |
| `POST` | `/api/reset` | 重置演示数据 |
| `POST` | `/api/diff` | 提交版本对读（`article_id`、`new_text`、可选 `compute_delay_ms`），返回新版本号 |
| `GET` | `/api/diff` | 最新版本的比对状态与结果（pending/running/done/stale/failed） |

`compute_delay_ms` 用于在演示中人为制造慢重算/慢比对（0~30000 毫秒），观察并发改条件、
改稿与过期保护行为。交互式文档见 `/docs`。

## 版本对读（修订稿比对）

技术编辑审阅修订稿时，在页面底部“版本对读”面板操作：

1. **选原稿**：从 30 篇库内文章下拉选择一篇作为原稿，原文即时显示；
2. **贴新稿**：粘贴不超过 **1200 字**、切句后不超过 **10 句** 的修订稿
   （输入框下方实时显示字数/句数，超限变红且服务端拒绝 422）；
3. **切句**：双方文本均按 `。！？` 切句，句末标点归入本句，记录每句在原文中的
   字符范围 `[start, end)`；
4. **相似度**：使用**与推荐模型完全分开**的字符 2~3 元 TF-IDF —— 每次比对新建
   `TfidfVectorizer(analyzer="char", ngram_range=(2,3))`，仅在本次比对的旧句、
   新句与相邻两新句拼接文本上 fit；推荐系统的文章拟合单例不受影响；
5. **候选配对**：旧句 × 单个新句、旧句 × 相邻两新句的拼接文本，余弦相似度
   **低于 0.35 的一律不配对**；
6. **全局最优对齐**：在“每个旧句至多配对一次、每个新句至多被占用一次”约束下，
   用 DFS + 分支定界求**全篇相似度总和最高**的对应方案；匹配不要求保序，
   因此**允许拆句后调序**；
7. **分类标注**：
   - **对应**：配对两句文本完全一致；
   - **改写**：单句对单句、相似度 ≥ 0.35 但文本不同；
   - **拆句**：旧一句对相邻新两句；
   - **移位**：按旧句顺序看，配对的新句下标不在最长递增子序列中（附加标签）；
   - **新增**：未配对的新句；**删除**：未配对的旧句；
8. **并排对读**：每行左侧旧句、右侧新句（拆句时两句），均标注原文字符范围，
   中间显示类型徽章与相似度；新增/删除行单侧留空；
9. **迟到保护**：比对是异步任务，每次提交版本号 +1，旧任务立即标记 `stale`；
   worker 写回前再次核对版本号，**改稿后迟到的旧比对结果绝不落库覆盖新稿**；
   前端也只渲染本地最后提交的版本号，双重保险。`compute_delay_ms` 可制造慢比对
   现场演示该行为。

## 目录结构

```
app/
  articles_data.py      # 30 篇本地文章语料
  tfidf_model.py        # 推荐用：仅文章拟合的字符 2~3 元 TF-IDF 单例
  revision_aligner.py   # 版本对读：切句、独立 TF-IDF、全局最优对齐与分类
  optimizer.py          # 精确全局最优求解器（枚举 + 分支定界）
  database.py           # SQLite 持久化、世代/版本、票据、串行写事务
  worker.py             # 推荐后台异步重算线程与过期/失败处理
  diff_worker.py        # 比对后台线程（与推荐 worker 独立）
  main.py               # FastAPI 路由与生命周期
  static/               # 演示网页（index.html / app.js / style.css）
tests/                  # 求解器对拍、TF-IDF 约束、端到端 API、版本对读测试
Dockerfile, docker-compose.yml, requirements.txt
```

## 已知边界与取舍

- 数据规模固定为 30 篇/6 位置，精确枚举最坏情况单次求解约 0.2 毫秒；
  若文章量大幅增长，需要替换为整数规划或带剪枝的搜索，接口层无需改动。
- 演示采用单会话全局状态（对应两个浏览器窗口共享同一进度的设定）；
  多用户隔离需要再引入会话 ID 维度。
- 并发去重的宽限窗口是时间启发式（默认 2 秒）：足以覆盖线程调度、双击与网络重试，
  又远小于人工两次点击间隔；可通过环境变量调整。
